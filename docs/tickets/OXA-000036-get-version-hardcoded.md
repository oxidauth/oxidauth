## Problem

The register line reads: "`get_version()` ignores the server header, hardcodes `"0.1.0"`; `build_authorization` emits no header for `BoxedError`/`Other`-kind errors." **Neither clause describes code that exists in this repository, in any state.**

1. `get_version()` does not exist in the SDK, never existed in the committed history, and no test pins any such method. There is no server version *header* to ignore — the version travels in the JSON body of the unauthenticated `GET /api/v1/__meta/{healthcheck,livecheck}` endpoints (`health.rs:16`, `live.rs:8`; envelope serializer `xlib/http/src/lib.rs:146–147`). No literal `"0.1.0"` exists anywhere in oxidauth-rs; the crate is at 0.9.0 and was at 0.4.0-rc2 at the earliest commit that touched its manifest.
2. `build_authorization` does not exist (independently established in `OXA-000028:16`); `ClientErrorKind` has no `BoxedError` variant (`client/mod.rs:598–607`). Every failure path that could plausibly be meant here returns `ClientError { kind: Other(msg), source: Some(boxed) }` and **propagates `Err` before any request is sent** (`:248–261`, `:280–298`, `:391–409`) — failing closed with no header is correct behavior, not a defect.

The genuine residuals worth keeping are P3 at most: (a) the SDK offers **no way to query the server's version/health** — consumers must hand-roll reqwest against `/api/v1/__meta/*` even though the DTOs (`oxidauth-http::__meta`) already exist; (b) the only hardcoded version-ish constant in the SDK is the **API prefix `"/api/v1"`** in `Client::new` (`:107–109`), pinned without a marker by the two tests at `:1494–1503`/`:1505–1530` — plausibly what the register's "(pinned, no marker)" parenthetical was about.

## Analysis

**Likely provenance of the phantom (inference, marked as such).** The register (dated 2026-09-29) was compiled from test-migration implementer reports whose added tests are **uncommitted working-tree code** (`git status` shows the SDK/services test files as `M`). The string `get_version()` does exist in the tree today — but only as **`Uuid::get_version()` UUID version-bit pins** in campaign-added tests: `oxidauth-services/src/authorities/update_authority.rs:376–380`, `create_authority.rs:190–194`, `seedz/src/fixtures.rs:569`; `missing-tests.md:526` and `:391` describe exactly those "genuine version-bit check (`get_version() == Some(Version::Random)`)" pins. "0.1.0" matches the **vendored xlib manifests**, which the migration plan deliberately kept at `version = "0.1.0"` (`docs/migration-plan/03-vendor-xlib-crates.md:147–148`, `04-provider-wiring.md:29`, `06-telemetry-boot-sequence.md:32`) until the later 0.9.0 workspace bump. "BoxedError/Other" matches two real error shapes — the kernel's wire-visible `name: "BoxedError"` (`error.rs:35`) and the client's `ClientErrorKind::Other` (`client/mod.rs:606`) — that a garbled report could fuse into an invented `build_authorization` mechanism. Conflating these into an SDK-version bug is consistent with the confirmed campaign-wide drift pattern (cf. OXA-000027 §Problem, where the same CLI section's line numbers pointed at markers, not defects).

**Why the second clause has no defect even charitably read.** Header installation happens only on auth/refresh *success*; every failure arm returns `Err` and the state machine never dispatches (`authenticate_if_needed` propagates `refresh()`'s error, `:443–448` + `:462–463`). So there is no code path where an "error kind" silently suppresses the header. **One adjacent, real, and unpinned behavior** does exist, and it is the only "no header emitted" defect-shaped fact in the area: when no JWT was ever obtained, `check_auth_state` returns `AuthState::Auth` and `authenticate_if_needed` returns `Ok(false)` (`:429–431`, `:446`), after which `request()` proceeds to send the call with `State::default()`'s plain `reqwest::Client` — no `Authorization` header, **no error** (`:462–474`; `State` default at `:97–103`). The server's 401 failure envelope then comes back and, for raw wrappers, is returned as `Ok` — that downstream leg is exactly CLI-5/OXA-000031 (`contract.rs:230` pin). No test exercises `request()` without auth (the E5 harness injects auth state, `users/contract.rs:7–8,55–59`; all `NoJwtFound` asserts target the `get_jwt` accessor, `client/mod.rs:858–860,895–900,921–926,1524–1529`).

**Cross-ticket contamination.** Two already-written tickets propagate the phantom as if verified: `OXA-000027:68` ("the SDK's `get_version` wart is CLI-10") and `OXA-000028:59` (lists "CLI-10 (`get_version` hardcode)" as out-of-scope). `OXA-000028:16` is the honest one — it grep-verified `build_authorization` absent. This ticket supersedes the phantom references; the risk if left uncorrected is a future agent "fixing" a method that doesn't exist or, worse, fabricating `get_version()`/`build_authorization` to make the register true.

**Who is affected today:** no runtime behavior (nothing calls a nonexistent method); the affected population is register/ticket consumers, plus SDK consumers who want server-version introspection and must bypass the SDK to get it.

## Impact

- **As-described: zero.** No user-visible defect exists; the register line is misinformation, which in this campaign's workflow is itself damaging — it misdirects fix effort and invites implementation of fictional APIs.
- **Real gap (P3):** SDK consumers cannot perform version negotiation / server-identity checks (e.g., refusing to talk to an old server) without hand-rolled HTTP; the healthcheck endpoint is already unauthenticated and hurl-covered server-side, so the capability exists at the wire but not in the crate.
- **Test-surface honesty:** the "pinned, no marker" note attaches to `/api/v1`-prefix pins (`:1494–1503`), not to any version method; those pins document intentional URL-shape behavior and are not a bug — the api nests routers under `/api` + `/api/v1` (`server/mod.rs:33`, `api/v1/mod.rs:18–20`) and there is no version-disclosure mechanism the SDK should honor for the prefix.
- **Adjacent silent-dispatch behavior** (unauthenticated `request()` with no header, no error) is real but only observable through OXA-000031's envelope-passthrough; it deserves a register row of its own or absorption into OXA-000031's scope, not this ticket.

## Proposed resolution

1. **Correct the register; do not "fix" the phantom.** Replace `BUGS_AND_NOTES.md:60` with the accurate residual, e.g.: *"CLI-10 (corrected): SDK has no `get_version`/`__meta` wrapper (version lives in `__meta` JSON body, not a header); `/api/v1` prefix hardcode pinned at `client/mod.rs:1494/1505` without a marker — intentional, not a bug."* Strike the `build_authorization` clause; it was already disproved in `OXA-000028:16`.
2. **Fix the propagating references:** annotate `OXA-000027:68` and `OXA-000028:59` ("CLI-10 `get_version` hardcode") with "superseded by OXA-000036 — phantom; no such method."
3. **Optional, small, recommended (the only code change in scope):** add an **inherent** `Client::get_version()` (follow the `get_public_keys` pattern at `client/mod.rs:182–224`: raw `reqwest`, no auth-state machine, since `__meta` answers without auth per `healthcheck.hurl:1`): `GET {base_url}/__meta/livecheck` (`base_url` already ends at `/api/v1`, `:107–109`, so the route composes to `/api/v1/__meta/livecheck`; prefer `livecheck` — DB-free, `live.rs:4–11` — over `healthcheck`, which pings the DB and returns 500/`healthy:false` on DB failure, `health.rs:11–27`). Return the typed `oxidauth_http::__meta::livecheck::LivecheckRes` (or a small `{version, healthy}` view). Errors: `ClientErrorKind::Other("unable to fetch server version")` with boxed source, same as siblings. **No hardcoded fallback literal** — the register's "hardcoded value as fallback" has no real analogue because there is no header; if callers want a local expectation they already have `env!("CARGO_PKG_VERSION")` at their own call sites. Keep it inherent, not on `ClientTrait`: adding a trait method is a breaking change for every consumer implementing `ClientTrait` and would require the `ClientMock` impl (`client/mod.rs:87–89`, `crate::mock`) to grow the method; `get_jwt`/`request` precedent (`:148`, `:452`) shows inherent methods are the crate's convention.
4. **Pin handling:** this ticket flips **no `BUG(pinned)` assertion** — none exists for it (markers in `client/mod.rs` are CLI-2/3/4 only; `:966/:1074/:1290`). The `/api/v1`-prefix tests (`:1494–1503`, `:1505–1530`) stay untouched and unmarked: they pin intentional behavior. If step 3 lands, it ships with *new* tests (below), not flips.
5. **Hand off the adjacent finding** (silent unauthenticated dispatch at `:446`→`:462–474`) to OXA-000031's owner as a candidate companion fix — e.g., fail `request()` with `ClientErrorKind::NoJwtFound` when `authenticate_if_needed` returns `Ok(false)` — noting that fix would need a check against every wrapper contract test (all authenticate via state injection first, `users/contract.rs:55–59`, so they should be immune) and its own register row; deliberately **not** done here.
6. **Compat (step 3):** additive inherent method — zero impact on `ClientTrait`, `ClientMock`, wiremock contract harness, or server. Server, DTOs, hurl untouched. Record in `changelogs/`.
