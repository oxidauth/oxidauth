## Problem

T-7's conclusion ("not new debt") survives; every mechanism claim in the line does not.

1. **"Service::call is deprecated" — wrong object.** No attribute marks the method. The attribute is on the trait (`service.rs:4-9`), plus separate ones on `CanLayer`/`CanService` (`:24-27`, `:51-54`). "deprecated method `Service::call`" messages exist only as rustc's inherited phrasing at *call sites* (probe §Analysis 1) — as do "deprecated associated type `Service::Response`" messages, which T-7 never anticipated. The register's parenthetical framing ("the fn returns `Box<dyn Future>` / async-trait desugaring" folklore the line is loosely echoing) is doubly dead: `Box<dyn Future>` was replaced by `#[async_trait]` in commit `d93f58a`, and async-trait desugaring is irrelevant — the lint is driven purely by the attribute's presence at named path sites.
2. **"on the mandated `#[async_trait]` mock convention" — the mock half is real but already solved, and mockall is fiction.** The mandated convention is *hand-written* `#[async_trait] impl Service<…> for Mock…` blocks in `#[cfg(test)]` mods (105 of them in `oxidauth-services`, plus api's `MockService`); `mockall` is an unused dev-dep of `oxidauth-rs` only, and SDK mocks (`ClientMock` implementing the SDK's own `*Trait`s) never touch kernel `Service` — that is OXA-000034's separate shadowing story, don't conflate. Every mock site is **already silenced** by 108 `#[allow(deprecated)]` attributes (services 60, postgres 46, api 2; `missing-tests.md:438` verified they suppress real lints). So mocks generate **zero** build warnings today; the "inherent noise" they'd produce was defused at the time it was incurred.
3. **"pre-existing `service.rs:29`" — stale in both word and number.** Nothing warnable is at `service.rs:29` today (it is the `permissions: Vec<Token<'a>>` field inside the deprecated `CanLayer` — a field of a deprecated struct never lints); the slice-era report cites the real attribute lines `4,24,51`. And no committed state ever deprecated anything: `git log -S` finds the attribute in 0 commits, HEAD's `service.rs` is attribute-free. "Pre-existing" warnings cannot exist — the warnings are *introduced by the uncommitted plan-09 attributes themselves*, against re-export/import/impl sites (`create_user.rs:10` etc.) that predate them.

## Analysis

**1. Lint mechanics, probe-proven on the pinned toolchain (standalone `rustc 1.98.0 --edition 2024` in `/tmp/oxa67`; no repo crate built, no repo file touched).** A same-crate lib probe and an rlib+consumer probe (mirroring kernel/repository/postgres shapes) establish, each as an independent warning message per named path site: named `use` and `pub use` of the deprecated trait **warn** (same- and cross-crate); `impl DeprecatedTrait for X` headers **warn** — including when the name arrives via a glob import; supertrait bounds, struct/fn bounds, and blanket-impl `where` clauses **warn**; `T::Response` warns as deprecated *associated type*; `x.call(…)` warns as deprecated *method* even on a concrete type; the glob-import line itself is **silent**; an impl-item's own `fn call`/`type Response` definitions are **silent**; a mod-level `#[allow(deprecated)]` silences the whole subtree; and — relevant to kernel's `Layer`/`CanLayer` self-uses — nesting a use inside *another* deprecated item does **not** suppress it.

**2. Applying the rules to the inventory gives the live warning surface, and it is not the mocks.** Suppressed: all 105 services mock impls + their 21 imports, api's impl/test-mod, postgres's 46 test mods. Un-suppressed named sites (static counts; one message each per §1):

| crate | sites | shape |
| --- | --- | --- |
| `oxidauth-kernel` | 37 + ~8 (+5 under `cfg(test)`) | 37 `pub use crate::service::Service;` re-exports in request modules; `service.rs` self-uses `:32/:40/:41/:44/:61/:63/:80` + unallowed test mock mod |
| `oxidauth-repository` | 148 (32 imports + 116 trait-refs) | `pub use` re-exports, `*Query` supertrait bounds, blanket-impl where-clauses; zero allows, zero test mods |
| `oxidauth-postgres` | 65 (7 imports + 58 impl headers) | non-test `impl Service<&'a Params> for Pg*Repository` (headers warn even where the trait arrives by glob) |
| `oxidauth-api`, `-rs`, `-cli`, `-import-export`, `-http`, `seedz`, `xlib` | 0 | fully allowed (api) or zero references |

So T-7's claim is **inverted**: the part that is truly inherent (hand-written mocks implementing a deprecated trait) is already paid for with allows and emits nothing; the ~250 messages that *do* fire are the plan-09 migration's progress meter — every layer that has not yet switched from `Service<&'a Params>` to the named `*ServiceTrait`/`*Query` traits still names the deprecated trait. "Not new debt" is right (it's the same known migration, note: "removed for 2.0", with `can.rs:1-7` explaining the last consumer); "inherent" is wrong — these warnings retire themselves when plan-09 retires `Service`, and silencing them now would *destroy* that meter.

**3. No escape is needed, and the proposed escapes are worse.** Renaming to `invoke` neither removes the trait attribute nor matches anything in-repo (the naming already chosen by plan-09 is the per-operation `*ServiceTrait` set; the tower-style `.call` is exactly what's being retired — `tower::Service::call` shares nothing here). Crate-wide `#![allow(deprecated)]` on `oxidauth-repository`/`oxidauth-postgres` would silence ~213 progress sites *and* every future deprecation in those crates. Scoping allows per site instead would take ~250 annotations to make a progress meter read zero — noise laundering, not a fix. The one defensible tightening is kernel's own unallowed `#[cfg(test)] mod tests` (`service.rs:100-161`) — but it retires with the trait, so leaving it costs five test-build warnings for the life of a migration already in flight.

**4. Register consequences beyond T-7 itself.** OXA-000064 §Analysis-5 sets up "T-7 … really is inherent … stays KEEP" as its counterexample; the can.rs-precedent citation at its `:19` stands, but the KEEP-scoping sentence needs the same correction this ticket lands. The register's "mandated `#[async_trait]` mock convention" phrasing also risks sending a future contributor to add `mockall` (dev-dep exists, unused) or to "fix" mocks that are already warning-free — and register T-3 means test-code mock warnings don't even surface under `cargo check`.

## Impact

- **Mis-scoped knowledge, zero code impact.** Nothing about current behavior, product, or runtime is at stake — this is entirely a lint-attribution record. The damage vector is the register itself: KEEP-noise-as-written licenses permanent tolerance of ~250 warnings ("inherent"), misdirects where to look (mocks, `:29`), and names an absent tool (mockall).
- **Warning desensitization during plan-09, acknowledged.** `cargo build -p oxidauth-kernel` / `-p oxidauth-repository` / `-p oxidauth-postgres` will each print dozens-to-148 deprecation messages per build in the current worktree; a genuine new warning of any lint buries in it. That is transient by construction (retirement kills it) and the correct interim remedy is the rewrite below — say what the noise *is* and when it dies — not annotation.
- The corrected posture is also the honest one for OXA-000064's comparison table: T-4's macro noise was fixable at the source (2 lines); T-7's live noise is fixable only by finishing the migration it measures — both are "don't enshrine", by different routes.

## Proposed resolution

**Disposition: FIX NOW — documentation only** (the code posture is already correct: allows exactly where the convention demands the deprecated trait, no allows where the warning is migration telemetry). Rewrite `BUGS_AND_NOTES.md:102`:

> **T-7** The working-tree `#[deprecated]` on kernel `service::Service` (`oxidauth-kernel/src/service.rs:4,24,51`; trait-level — not method-level, and absent from HEAD) makes ~250 named sites warn during plan-09: 37 kernel `pub use crate::service::Service` re-exports + `service.rs` self-uses, ~148 `oxidauth-repository` re-exports/trait-bounds, 65 `oxidauth-postgres` imports/impl headers. (Old line's "Service::call", "service.rs:29" and mockall framing were wrong; the warnings were never pre-existing — the uncommitted attribute introduced them.)

Follow-ups: correct the "stays KEEP" sentence in `OXA-000064:44` to point here (same commit), and when plan-09 retires `Service`, retire this line too rather than keeping a corrected-but-dead register entry.

Rejected: (a) **KEEP as written** — pins three false mechanisms and licenses permanent warning tolerance; (b) annotating repository/postgres (or kernel request modules) with `#[allow(deprecated)]` — erases the completion meter for the exact work plan-09 tracks, and masks all other deprecations in those crates if crate-level; (c) renaming `call`→`invoke` or adopting tower/mockall — invents work against a trait that dies at 2.0 and contradicts plan-09's own naming (`*ServiceTrait`); (d) touching the SDK mocks — wrong trait, wrong crate (OXA-000034).
