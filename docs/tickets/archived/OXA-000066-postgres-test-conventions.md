## Problem

T-6 is a conventions record, not a defect. The convention itself is real and perfectly uniform — but the register sentence is wrong in four of its five clauses, and the wrong mechanism ("per-test transaction rollback") has already propagated into module docs, the ledger (T-8), the audit ledger (`missing-tests.md`), and pending tickets (`000053`, `000054`). Fifteen open tickets (`000001`, `000006`, `000012`, `000013`, `000014`, `000017`, `000018`, `000019`, `000020`, `000022`, `000026`, `000039`, `000049`, `000053`, `000054`) already write or modify tests under these conventions, and more (e.g. `000002`) will. Codifying the register as written would canonically mis-document how isolation works, what `assert_sql_state` does, and what `Database::from_pool` accepts.

Clause-by-clause verification against the current code (register text in quotes):

1. **"`#[sqlx::test(migrator = "crate::MIGRATOR")]` is transaction-isolated" — convention ✓, mechanism ✗.** The attribute form is universal: 150/150 DB tests in `oxidauth-postgres` use it (the only two other `sqlx::test` text hits in the crate are comments — `test_fixtures.rs:4`, `auth/tree/mod.rs:392`). But sqlx 0.8.6 wraps nothing in a transaction; isolation is a **fresh database per test** (details in Analysis). There is no `tx` option in this version (`test_attr.rs` and `sqlx-core/src/testing` contain no transaction code path).
2. **"repositories take the pool by value → build them via `Database::from_pool(&pool)`" — half right; the literal won't compile.** `Database::from_pool` takes an owned `sqlx::PgPool` (`xlib/postgres/src/lib.rs:123-128`, clones it into both `write` and `read`). Call sites: 93 total — 68 × `Database::from_pool(pool.clone())`, 25 × `Database::from_pool(pool)` (moved after last use, e.g. `permissions/delete_permission/mod.rs:48`), **0 × `from_pool(&pool)`**. Canonical shape is the per-module helper `fn repo(pool: &PgPool) -> Pg<Entity>Repository { Pg<Entity>Repository::new(Database::from_pool(pool.clone())) }` (`settings/select_setting_by_key/mod.rs:41-43`, and `test_fixtures::create_authority/create_user` do the same at `:60,:82`).
3. **"(repository structs must `derive(Clone)`)" — true as a convention, wrong as a requirement, wrong causality.** All 16 `Pg*Repository` structs are `#[derive(Debug, Clone)]` (spot-checked `PgUserRoleGrantRepository` `user_role_grants/mod.rs:12-13`, `PgAuthRepository` `auth/mod.rs:5-6`). But the by-value pool holder is `Database` — whose `Clone` the macro itself derives — and nothing clones a *repository*: the API wires fresh repos from a cloned **`Database`** (`oxidauth-api/src/provider/services.rs:36-41`), and `rg 'repo\.clone\(\)'` across `src/` is empty. Repository `Clone` is uniform, cheap (pool handles are `Arc`), and currently unconsumed boilerplate.
4. **"cross-module integration tests take `db: Database`" — no such test exists.** Zero test fns take `db: Database`; sqlx 0.8.6 only supports `fn()`, `fn(Pool)`, `fn(PoolConnection)`, `fn(PoolOptions, ConnectOptions)` (`sqlx-core-0.8.6/src/testing/mod.rs:86-152`), and every test here takes `pool: PgPool`. `db: Database` is the repository *constructor* signature (`new(db: Database)` in all 16 entity modules). The real cross-module `db:` convention is in production code: the auth-tree read threads a single `db: &mut PgConnection` (`auth/tree/mod.rs:31-33,60-62,91-94`) through the per-entity query fns. Cross-module tests (e.g. `auth/tree`) instead take the pool and seed multi-table graphs via `test_fixtures` + a small raw-`exec` helper (`:136`).
5. **"`assert_sql_state` intentionally asserts OUTSIDE any tx (separate connection)" — false: it opens no connection and runs no query.** The entire body (`test_fixtures.rs:91-103`) downcasts `BoxedError` → `sqlx::Error`, matches `Error::Database`, and compares `db_err.code()` to the expected SQLSTATE. The "separate connection" story is a myth; what's true is that error-path asserting needs no DB access at all, and *state* asserting (plain `SELECT COUNT` via the pool) needs no separate connection either because writes commit immediately in each test's own database.
6. **"insert_user" — no such helper.** The fixture exports are: `default_authority_settings` (:32), `create_authority` (:44), `create_user` (:70, repository write path), `assert_sql_state` (:91), `seed_user` (:106), `seed_user_named` (:120), `seed_authority` (:132), `seed_authority_with_settings` (:148), `seed_role` (:165), `seed_permission` (:176), `seed_public_key` (:195), `seed_refresh_token` (:209), `seed_refresh_token_now` (:231), `seed_role_permission_grant` (:246), `seed_role_role_grant` (:255), `seed_user_permission_grant` (:264), `seed_user_authority` (:273), `seed_totp_secret` (:293) — note `seed_user_role_grant` is absent (owned by OXA-000053) and there are no `insert_*` helpers.

## Analysis

**MIGRATOR vs TEST_MIGRATOR (reconciling with T-1 / OXA-000061).** Both consts exist; they belong to different crates with different jobs, and there is no conflict. The project convention for database-backed tests is `crate::MIGRATOR` → `oxidauth-postgres/src/lib.rs:45` (pinned `sqlx::migrate!("./migrations")`, deliberately exported `pub const` via the macro's advanced 4-arg form so tests can name it). `TEST_MIGRATOR` lives only inside `#[cfg(test)] mod db_tests` of the vendored macro crate (`xlib/postgres/src/lib.rs:323`): a structural test that never connects (module doc `:302-306`: TEST-only env names, `connect_lazy`) and asserts the migrator is empty (`:361-364`); per OXA-000061 it is also the reason `./test-migrations` must exist at compile time. The macro doc (`xlib/postgres/src/lib.rs:15-37`) confirms the design: the 3-arg basic form auto-emits its own `pub const MIGRATOR`; the 4-arg form used here skips that (`migrator_const!(ident)` → empty, `:220-225`) precisely so the pinned const at `lib.rs:45` is the single migrator source for app *and* tests.

**How `#[sqlx::test]` actually isolates (sqlx 0.8.6, verified in the pinned registry source):**
- `Postgres::test_context` (`sqlx-postgres-0.8.6/src/testing/mod.rs:95-190`) connects to `DATABASE_URL` via dotenvy, registers the test in a `_sqlx_test.databases` table, and **`CREATE DATABASE "<test db>"`** (`:170-172`).
- `setup_test_db` (`sqlx-core-0.8.6/src/testing/mod.rs:245-274`) opens one connection to that fresh DB and runs `migrator.run_direct()` — this is where `crate::MIGRATOR` is consumed — then fixtures.
- `run_test_with_pool` (`:184-211`) hands the test a pool built with `max_connections(5)`, `idle_timeout(1s)` (`sqlx-postgres testing :174-189`). There is **no open transaction**; every statement commits for real.
- On success only, `cleanup_test` → `do_cleanup` → `drop database if exists` (`:29-39, :192-201`). A **failing test's database is left behind** for post-mortem; stale test DBs from before the binary started are swept at startup (comment `:22`, `cleanup_test_dbs` `:41-84`).

**Why the folklore persists and which conclusions survive it.** `test_fixtures.rs:4-7` ("wraps every test in its own transaction and rolls it back, so seeding STAYS per-test"), `missing-tests.md:331`, T-8's "(sqlx per-test transactions)" and `auth/tree/mod.rs:388-392` ("sqlx::test's transaction rollback still runs") all draw correct *conclusions* from a wrong mechanism: per-test seeding is required (it is), exact `COUNT` asserts are sound (they are — migrations seed no rows and each test owns its whole database), and the suite is parallel-safe (it is). Per-test-database is *stronger* than transaction isolation. What actually changes:
- **Nothing rolls back on failure.** The "rollback" in `000006`'s "transactional rollback tests" for `insert_totp_secrets` (and any future rollback-behavior test) is the **repository's own SQL transaction**, not sqlx's; a test that fails mid-write leaves its DB until the next run's sweep — harmless for isolation, relevant for disk hygiene and for anyone tempted to `psql` into the leftover DB (it still exists precisely because nothing rolled back).
- **No single-connection property exists.** The pool admits 5 concurrent connections; nobody may "rely on the per-test tx" for cross-query visibility — visibility works because everything commits. The `&mut PgConnection` threading in `auth/tree` exists for query recursion efficiency, not tx-riding.
- **Cost model:** every test = `CREATE DATABASE` + full `MIGRATOR` replay + `DROP DATABASE`. OXA-000001's "every postgres test pays the new migration" stays correct (via `run_direct` per test DB, not tx overhead); T-8's ~5 s / 150 tests figure and its `--test-threads=1` advice are unaffected in practice — the runtime note belongs to T-8's own ticket (OXA-000068 on the T-*→OXA-0000{60+N} numbering that `000061/000062/000063` establish).
- **Error-path tests don't touch the DB.** `assert_sql_state` is a pure error-inspection helper; SQLSTATE codes (`23505`, `23503`, `23514`, …) arrive on the failed statement's error, so the "assert outside any tx" caveat is meaningless and should be deleted wherever it appears.

**The one legitimate exception** to "always name the migrator": `xlib/postgres/src/ping/mod.rs:18` — the vendored crate's bare `#[sqlx::test]` pings an empty per-test DB and correctly needs no schema. It is not precedent for app crates.

## Impact

No product defect; this is documentation-integrity and onboarding risk:

- New test authors following the register verbatim write `Database::from_pool(&pool)` (compile error) or reach for an `insert_user` helper that doesn't exist, then hand-roll a 19th seed helper — the exact triplication OXA-000053 exists to stop.
- Wrong rollback folklore produces wrong test expectations: tests that assume failed writes vanish (they don't — the DB persists on failure), or that assume a hidden transaction to "join" (there is none), or that blame leftovers/DB counts on a phantom rollback. It also misdirects debugging when a repo-level explicit-transaction test behaves "wrong" — the behavior to inspect is the repository's SQL, never the harness.
- Every ticket that cites "T-6 conventions" (15 today; `000053:52` and `000054:57` quote the transaction wording directly) inherits and re-propagates the errors; the audit trail (`missing-tests.md:331`) records them as review evidence.
- Positive: because the convention is 100 % uniform (150/150 attribute sites, one `repo(&pool)` shape, one fixture module, one error-assert helper), codification is cheap — document what exists, correct the four clauses, and it becomes self-enforcing by copy-adherence.

## Proposed resolution

**KEEP the convention; FIX NOW the wording; codify in one canonical doc, then retire the register line.** The register entry is an action item whose resolution *is* the doc change.

1. **Create `docs/TESTING.md`** (no `CONTRIBUTING.md` exists; `docs/` already holds topical docs like `SECURITY_REPORT.md`). Outline:
   - **§1 Test entrypoints:** `bin/unit_test.sh` vs `src/oxidauth/database_test.sh` (repo-root `.env`, `MIGRATIONS_ENABLED=true`); gate everything test-affecting with `cargo test --no-run`, never plain `cargo check` (cross-ref T-3 / OXA-000063); note the `oxidauth-postgres` runtime expectation lives with T-8.
   - **§2 How sqlx isolation actually works (0.8.6):** CREATE DATABASE → `MIGRATOR.run_direct` → test on a ≤5-connection pool → DROP DATABASE on success; leftovers kept on failure and swept next run; no transactions anywhere. Include the source pointers from Analysis so the next reader can re-verify.
   - **§3 The conventions (corrected T-6 text):** (a) `#[sqlx::test(migrator = "crate::MIGRATOR")]` — always name `crate::MIGRATOR` (`oxidauth-postgres/src/lib.rs:45`); `TEST_MIGRATOR` is internal to `xlib/postgres`'s own tests (cross-ref OXA-000061); (b) construct repositories via `Pg<Entity>Repository::new(Database::from_pool(pool.clone()))` — `from_pool` takes the pool **by value** — through the `fn repo(pool: &PgPool) -> …` module helper; keep `#[derive(Debug, Clone)]` on repository structs for uniformity; (c) cross-module tests take `pool: PgPool` and seed via `crate::test_fixtures` (enumerate exports; `create_user`/`seed_user`, not "insert_user"; helpers take `&PgPool`, bind explicit columns, `.expect()` on execute); new seeds go **into** `test_fixtures`, not inline (OXA-000053); (d) assert constraint errors with `assert_sql_state(err, "23505")` — error downcast only, no DB access; (e) rollback tests exercise the repository's own SQL transaction.
   - **§4 Migration contract:** migrations must stay data-free (exact `COUNT` asserts depend on it); every migration replays per test.
   - **§5 Adjacent guards:** env/subscriber tests use the serial guards (T-5); non-terminating-behavior pins use the spawn-thread + `tokio::time::timeout` pattern (`auth/tree/mod.rs:344+`, the test OXA-000001 will flip).
2. **Correct the folklore in place, same change set:** `test_fixtures.rs:4-7` module doc; `auth/tree/mod.rs:388-392` comment tail ("the connection is returned to the pool; sqlx keeps the leftover test database / drops it on success" — the observed timing claim stays); `missing-tests.md:331` wording; `OXA-000053:52` wording (coordinate with its owner — it also owns the fixture list). Do **not** touch `000006`'s "transactional rollback tests" phrase — it correctly denotes the repo's own tx.
3. **Retire `BUGS_AND_NOTES.md:101`:** replace the line with a one-line pointer — "T-6 → docs/TESTING.md §3 (conventions codified, mechanism corrected)". Correct T-8's "(sqlx per-test transactions)" parenthetical at `:103` within its own ticket rather than silently.
4. **Rejected alternatives:** (a) keeping the register line as the canonical text — it is wrong in 4/5 clauses and every consumer copies it; (b) "fixing" the tests toward real transaction isolation — per-test databases give strictly stronger isolation and the pool-by-value `Database` design would need to change shape for a tx that buys nothing; (c) introducing a tx-based helper (e.g. wrapping each test body in a `pool.begin()` and threading `&mut Transaction`) — it would fight `Database::read_pool()`/`write_pool()` (reads would bypass the tx) and break the uniform `repo(&pool)` pattern used at 93 sites.
